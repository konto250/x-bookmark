# ポストノート / x-bookmark

Xのポストをブックマークレットから取り込み、本文とリンク先の内容をOpenAI APIで分類して、タグと一緒にブラウザーへ保存するアプリです。

公開URL: https://x-bookmark-lemon.vercel.app

## 使い方

1. ログイン画面で、管理者が設定したパスワード（従来のアプリ用アクセスコード）を入力します。認証はHttpOnly Cookieで30日間保持します。パスワードをlocalStorageには保存しません。
2. 「ブックマークレットを設定」を開き、「ポストノートに保存」をブラウザーのブックマークバーへドラッグします。
3. Xで保存したいポストの日時をクリックして詳細ページを開きます。長文は「さらに表示」で展開します。
4. ブックマークレットを実行すると、アプリの新しいタブに本文が取り込まれます。本文のハッシュタグを自動でタグにし、それ以外の関連タグをAIが追加提案します。AIが利用できなくても、本文のハッシュタグは取り込めます。
5. 不要なタグをクリックして外し、任意のタグを追加して保存します。ハッシュタグとAIタグの重複はまとめます。外したタグは保存後の再編集でも自動追加されません。必要なら手動で追加し直せます。
6. 一覧から元のポストを開けます。タグでの絞り込み・タグ別のグループ表示・本文検索・編集・削除に対応します。

ブックマークレットを利用できないブラウザーでは「ポストを追加」からURLと本文を入力できます。画面右上の「バックアップ・復元」からJSONファイルの保存と復元ができます。

## バックアップ・復元

1. 右上の「バックアップ・復元」を開き、「JSONファイルを保存」を押すと全件のバックアップをダウンロードします。検索やタグの絞り込みは書き出し対象に影響しません。
2. 復元するときは「バックアップファイルを選ぶ」でJSONを選択します。ファイル名・件数・既存ポストとの重複件数を確認できます。この時点では保存データは変更しません。
3. 「追加・統合する」は既存のポストを残し、同じポストの本文・タグ等をバックアップで更新します。最初の保存日時は維持します。「すべて置き換える」は現在のブックマークを削除し、バックアップの内容と保存日時に戻します。
4. 「復元する」を押し、確認画面で確定します。置き換える前に現在のデータもバックアップしてください。

本文・投稿者・タグ・自動追加から除外したタグ・リンク先の情報・保存日時を引き継ぎます。AI認証・下書き・提案キャッシュは対象外です。ファイルはブラウザー内だけで処理し、サーバーへのアップロードやAI呼び出しはありません。別のブラウザーや端末への移行にも使えます。

読み込み上限は50MBです。以前のバージョン1のバックアップとポスト配列形式にも対応します。同じポストがファイル内に複数ある場合は末尾の内容を使います。不正ファイルは保存前に拒否し、容量不足時も既存データを残します。

## AI費用の節約

- 自動提案を維持し、既定モデルを `gpt-6-luna` に変更しました。推論を `none` に設定し、説明文を生成せず、最大6個のタグだけを返します。出力上限は256トークンです。失敗時の自動再試行・別モデルへの自動切り替えは行いません。
- AIへ送る本文は先頭4,000文字、リンク先は最大5件で各本文1,000文字・タイトル160文字・説明240文字に制限します。ハッシュタグは本文全体から無料で抽出します。長文の後半にある主題はAI提案に反映されない場合があります。ブックマークの本文保存上限は従来どおり30,000文字です。
- 同じポストURL・本文・リンク・モデル・解析仕様の成功結果を、同じブラウザー・同じサイト内で30日間再利用します。再利用時はリンク取得もOpenAI API呼び出しもありません。タグの追加・削除だけでは再課金しません。リンク先の内容が更新されても期限内は自動検知しないため、必要なら「再解析（API使用）」を押してください。
- キャッシュは `postnote.analysis.v1` に最大100件・JSON文字数500,000まで保存します。期限切れ・件数超過による削除・ブラウザーデータの削除後は再取得します。保存機能が使えない場合は通常の解析を行います。Web Locks対応ブラウザーでは、別タブからの同時解析も待ち合わせます。異なるブラウザーや端末間では共有しません。
- 2026-10-21確認の標準料金は100万トークンあたり入力$0.10・出力$0.50です。例えば入力2,000・出力80トークンなら1回約$0.00024、1,000回約$0.24です。実額はトークン数により変わり、料金も変更され得ます。[OpenAI公式のモデル料金](https://developers.openai.com/api/docs/models/gpt-6-luna)

対象を自動判定できないXの画面では、保存する本文を選択する画面が表示されます。本文取得に失敗する場合やコード更新後は、アプリを再読み込みし、登録済みのブックマークレットを登録し直してください。ブラウザーに登録したコードは自動では更新されません。

## ローカル起動

Node.js 22以上を使用します。

```powershell
npm install
node scripts/setup-local.mjs
# .env.local の OPENAI_API_KEY を設定
npm run dev
```

`http://127.0.0.1:5173` を開きます。`.env.local` の `APP_ACCESS_TOKEN` がログイン画面で入力するパスワードです。ローカルAPIの環境変数は起動時に読み込むため、変更後はサーバーを再起動します。認証を含む確認には `npm run dev` を使ってください。`vite preview` 単独ではAPIやサーバー側のアクセス制限を起動しません。

| 環境変数 | 用途 |
| --- | --- |
| `OPENAI_API_KEY` | OpenAI APIキー。サーバー側だけで使用 |
| `OPENAI_MODEL` | モデル名。省略時は `gpt-6-luna` |
| `APP_ACCESS_TOKEN` | アプリ全体のログイン用パスワード兼Cookie署名用シークレット。32文字以上のランダムな値を使用 |

`.env.local` はGitとVercelへのソースアップロードから除外しています。ブラウザーへ環境変数を展開する `VITE_` 接頭辞は付けません。

## Vercelへ公開

フロントエンドはVite、`api/analyze.js` はVercelのNode.js Functionです。

```powershell
npm exec --yes --package=vercel -c "vercel link --yes --project x-bookmark"
npm exec --yes --package=vercel -c "node scripts/vercel-env.mjs"
npm exec --yes --package=vercel -c "vercel deploy --prod --yes"
```

環境変数設定スクリプトは `.env.local` の3変数を本番環境へ登録します。値は標準入力で渡し、ログやコマンド引数に表示しません。Vercelの管理画面から同じ変数を登録しても構いません。変更後は再デプロイが必要です。

モデルだけを更新する場合は `npm exec --yes --package=vercel -c "node scripts/vercel-env.mjs --model-only"` を使います。

ブックマークレットは表示中のアプリのオリジンを使用します。本番用の固定URLで登録してください。デプロイごとのURL・localhost・別のドメインは別の保存領域になります。

## ログインとアクセス制限

- Vercel Routing Middlewareが、未認証の画面・アプリのJavaScript・APIへのアクセスを遮断します。ログイン画面の静的ファイルと `/api/session` のみ公開します。環境変数未設定時はログインを許可しません。認証応答と保護対象は `private, no-store` でキャッシュさせません。
- パスワードはHTTPS経由でサーバーに送り、Vercelの環境変数 `APP_ACCESS_TOKEN` と照合します。ブラウザーのlocalStorageやsessionStorageにはパスワードを保存しません。署名付きCookieに `HttpOnly; Secure; SameSite=Strict` を付け、30日で期限切れにします。ローカルHTTP環境のみ `Secure` を省きます。
- Xからの取り込み時に未ログインでも、URLフラグメントの本文はログイン後に引き継ぎます。ログイン済みなら自動で進みます。ログアウトするとCookieを削除し、同じ保存領域の別タブにも画面を閉じる通知を送ります。ブックマークは削除しません。
- ログイン試行はインスタンス内でIPあたり5回/分に制限します。分散環境全体の厳密な制限ではないため、セットアップが生成する長いランダムなパスワードを使ってください。認証処理ではOpenAIを呼びません。
- パスワードを変更するには `.env.local` とVercelの `APP_ACCESS_TOKEN` を更新し、再起動・再デプロイします。以前の署名Cookieは無効になります。通常のログアウトはそのブラウザーのCookie削除で、盗まれたCookieの個別失効を管理するDBはありません。
- この機能は公開アプリへのアクセス制限です。localStorageのブックマークやJSONバックアップを暗号化しません。同じ端末・ブラウザープロファイルを操作できる人からの保護には、OSの画面ロックも必要です。

## 保存と外部通信

- ブックマークは `localStorage` の `postnote.bookmarks.v1` に保存します。保存するのはポストのURL・本文・投稿者・タグ・リンク先のタイトル等です。ブックマークのサーバーDBはありません。
- 取り込みデータはURLのフラグメントで渡し、読み取り後にアドレスバーから除去します。取り込み途中の下書きはタブ内の `sessionStorage` に保持します。
- AI提案時は本文・本文中のURL・既存タグをアプリのAPIへ送信します。サーバーがリンク先の公開HTMLを取得し、その内容をOpenAIのResponses APIへ送ります。API呼び出しは `store: false` を指定します。OpenAI側のデータ取り扱いは同社のAPIポリシーに従います。
- ブックマークは同じブラウザー・同じオリジンに限って共有されます。端末間の自動同期はありません。ブラウザーデータの削除で失われるため、必要に応じてJSONバックアップを書き出してください。
- 同じポストを再保存すると、最初の保存日時を保ったまま内容とタグを更新します。壊れた保存データを空データとして上書きしません。

## リンク解析と制約

- 本文は最大30,000文字、解析対象は最初の5リンク、1ページあたりHTMLは最大1MB・抽出本文は最大10,000文字です。
- 各リンクは最大8秒・4回までのリダイレクトで取得します。内部IP・localhost・特殊ポート・認証付きURLを拒否し、検証済みの公開IPに接続先を固定します。転送先も再検証します。
- ログイン必須ページ・PDF・JavaScriptで本文を生成するページ・取得拒否されたページは十分に読めない場合があります。取得できなかったリンクは画面に明示し、利用できる本文だけでタグ提案します。
- Xのログイン情報・Cookieは取得せず、ブックマークレットがその時点で表示されている本文を読みます。画像・動画の内容は解析しません。
- XのDOM変更やブラウザーの制限によりブックマークレットが動作しなくなる場合があります。手動入力で保存できます。
- AI解析にはログイン認証と、インスタンス内でIPあたり12回/分の簡易制限があります。この回数制限は分散環境全体の課金上限ではありません。利用予算はOpenAIのプロジェクト側でも管理してください。

## 検証

```powershell
npm test
npm run build
node scripts/check-built-bookmarklet.mjs
node scripts/smoke.mjs http://127.0.0.1:5173
```

単体・DOMテストはOpenAIの応答を模擬して実行します。`smoke.mjs` は未認証アクセスの遮断・正しいパスワードでのログイン・Cookie属性・キャッシュからの漏えい防止・ログアウトをHTTPで検証します。`--llm` を追加した場合のみ、`.env.local` のキーで実際のOpenAI APIにテスト文を送信します。

2026-10-21時点で67件の単体・DOMテストと本番ビルドを確認しました。未認証アクセス拒否・Cookie改ざん拒否・ログアウト・ログイン後の取り込み継続、バックアップの全フィールド復元・統合・置き換え・破損ファイル拒否、AI入力上限、キャッシュ期限・再利用・明示的な再解析・失敗後の再試行、本文ハッシュタグとAIタグの併用・重複除去・削除状態の保持、日時がtime要素ではない詳細画面、引用ポスト、固定リンクがない場合の本文選択を含み、本番バンドルから生成したブックマークレットの本文取得も検証しています。初回公開では、本番URLのHTTP 200、アクセスコード認証、TypeScript公式ページの取得、OpenAI実通信を確認し、「TypeScript」「公式ドキュメント」「プログラミング学習」「開発」の提案を受け取りました。実ブラウザーでの表示・X上でのブックマークレット実行は、この作業環境でブラウザーを操作できないため未確認です。

公開後に主要機能が動かなくなった場合は、VercelのDeploymentsから直前の正常なデプロイへ戻します。ブラウザーに保存したブックマークはデプロイの切り戻しでは削除されません。
